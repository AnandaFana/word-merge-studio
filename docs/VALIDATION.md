# 本地验证记录

验证日期：2026-09-10。交付对象是软件原型与源码，下面区分结构正确性、浏览器功能和 Office 排版验证。

## v0.2 增量验证

- 总计 **35 项测试通过**，生产构建通过。包含真实样本在双向底稿、左/右/智能三种格式下的六组合回归：正文完整一致、每段统一为单一 run、非正文文件内容保持与底稿一致。
- 六组合真实样本回归曾两次被 Vitest 默认的 5 秒测试期限中断；针对这一项将测试期限显式设为 20 秒后完成。应用中的字符对比和正文对比超时限制未放宽。样式链与主体格式结果加入只读缓存，避免界面反复解析同一份样式。

- 端口冲突实测：5173 已占用时，新启动实例打印 `Port 5173 is in use, trying another one...`，并成功监听 `http://127.0.0.1:5174/`；浏览器已打开该地址。使用 Vite 原生递增重试机制，不是随机猜端口。参考 [Vite 官方端口说明](https://vite.dev/config/server-options#server-port)。
- 新增独立格式回归：右文左格式、相同文字只改格式、全局智能统一、插入正文不继承标题、相同样式 ID 的左右定义冲突、源样式继承、主题字体/颜色解析、复杂块/自动编号拒绝、两侧都保留时的格式覆盖。
- 修复普通 run 没有 `rPr` 时错误借用末尾 run 格式的问题，有独立回归用例。
- 浏览器已操作“第 4 块选右 + 左侧段落格式”，界面明确显示“内容：右侧 / 格式：左侧统一”。
- 原生 Office 分页及内置浏览器下载落盘边界保持下文原记录，不因新增格式选项而提升验证级别。

测试覆盖左右格式基准、无操作整包字节一致、普通段落变更、字符格式跨 run 保留、替换位置格式继承、新段插入与删除、两侧都保留、清空正文、同结构表格内容变更、复杂块保护、表格结构变化拒绝、域/修订/书签锁定、XML 特殊字符、制表符与换行、重复调用不改变输入、无效文件与宏拒绝、示例合并。

真实样本由工作目录中的两份文件在本机读取，不打包进应用：

| 格式底稿 | 采用的正文 | 输出结果 |
| --- | --- | --- |
| 本地样本 A，19 块 | 本地样本 B，34 块 | 34 块，逐块文字完全一致 |
| 本地样本 B，34 块 | 本地样本 A，19 块 | 19 块，逐块文字完全一致 |

两方向合并后，除了 `word/document.xml`，其他所有非目录 ZIP 成员内容均与各自底稿逐字节一致。测试输出保存在本地被忽略的 `.qa/` 中，不作为人工定稿交付，也不会覆盖原文件。

自动测试按文件系统返回的顺序将两份文件标为 left/right；浏览器中的左右来自用户选择，两者标签不必相同。上表以文件名标识，避免混淆。

## 尚未确认

- 尝试运行 documents 技能的 `render_docx.py`，失败原因为 `LibreOffice soffice.exe was not found on PATH`。已查看脚本解析路径与日志，当前 Windows 运行时未提供 LibreOffice。因此未完成 Office 引擎的 PDF/逐页 PNG 检查，也未声称最终分页保真。
- 内置浏览器中的 Blob 下载已触发应用生成流程，但自动化工具未报告 `download` 事件，默认下载目录也未确认落盘。已增加实际 DOM 下载链接作为可见回退入口。请通过 `start.cmd` 在系统浏览器使用；Chrome / Edge 的实际下载落盘仍需一次人工验收，不能用 UI 的成功提示代替落盘证据。
- 尚未覆盖大规模真实 Word 语料、多节排版、公式、脚注、嵌入对象资源迁移、原生修订记录、三方合并、跨浏览器和辅助技术完整兼容性。
- 原版和合并预览的完整页数、最终打印效果未经 Word/WPS 验收。

## 建议验收

在系统 Chrome / Edge 中打开本地工作台，选择两份实际 Word，保留一侧格式并采纳另一侧的一处文字；导出后确认下载目录出现 `.docx`，在 Word 中打开核对字体、缩进、表格、页眉页脚和分页。复杂结构的禁用操作是当前明确的产品边界，应单独列入下一阶段开发。
