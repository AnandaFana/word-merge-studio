Word 的文字好复制，格式却很难听话。Word Merge Studio 把内容选择、章节结构和格式设置放进一个本地工作台，让你看清楚、选明白，再导出一份可继续编辑的 Word。

无需账号，无需上传文档，无需 AI 密钥。文件在浏览器内处理；首次安装依赖需要联网，安装完成后可在本地启动使用。

## 三种合并方式

| 工作区 | 适合什么场景 | 你可以做什么 |
| --- | --- | --- |
| **对比合并** | 同一份文档的两个版本 | 并排逐字对比；文字与段落格式独立选择；撤销操作 |
| **合并 Word** | 第一章、第二章等分章稿件 | 调整文件顺序；原格式拼接；识别并修正大纲；按类型统一格式 |
| **按章节融合** ✨ | 多份结构相似的报告、方案 | 对应章节归组；编辑标题；卡片移动与取舍；输出三级导航 |

例如，把三份报告各自的“目标”集中到一个大章节，再合并各自的“计划”：

```text
报告 A            报告 B            合并后的 Word
├─ 概述           ├─ 概述           ├─ 概述
├─ 目标           ├─ 目标           │  ├─ 报告 A
└─ 计划           └─ 计划           │  └─ 报告 B
                                   ├─ 目标
                                   │  ├─ 报告 A
                                   │  └─ 报告 B
                                   └─ 计划 …
```

每张内容卡片随带原文、表格和图片。保留来源正文格式，或者按正文、标题、题注和表格文字分别统一字体与字号，由你选择。

## 快速开始

安装 **Node.js 22.13 或更新版本**，然后克隆仓库：

```bash
git clone https://github.com/AnandaFana/word-merge-studio.git
cd word-merge-studio
npm ci
npm run dev
```

Windows 用户也可以下载 ZIP 并解压，直接双击 **start.cmd**。启动脚本按需安装依赖并打开浏览器；端口占用时会继续尝试其他端口，以终端打印的 `Local` 地址为准。

右上角支持 **中文 / English** 切换，并记住本机语言偏好。切换界面语言不会翻译或改写文档内容。

## 一分钟试用章节融合

1. 主页选择 **按章节融合**，点击 **体验三个示例**。
2. 查看“社区花园、社区书屋、街角咖啡”三份虚构方案，包含相同章节、不同字体、图片和表格。
3. 用箭头重排分组与卡片，修改来源标题，通过“移动到”调整归组，取消不需要的卡片。
4. 选择格式，预览结果，点击 **导出 Word**。
5. 在 Word 的 **视图 → 导航窗格** 查看“大章节 → 来源小标题 → 原有子标题”三级结构。

真实文档可以选择按标题配对，或明确选择按章节顺序配对。没有标题的内容也会单独留下来。识别采用本地规则，需要人工核对，不会调用在线 AI 自动润色。

## 格式究竟保留什么？

章节合并与章节融合会迁移支持的段落、表格、列表、超链接与嵌入图片，并隔离不同来源的样式和编号。图片复制原始字节；选择统一格式时，修改指定类型的文字格式，保留表格结构。

**页面尺寸、页边距、页眉页脚与主题采用第一个保留的来源文档，原有分节移除。** “保留格式”指来源正文格式，不代表完整保留每份原稿独立的页面布局。章节融合会新建组织标题，并将导航整理为三级；更深标题转为正文。

两版本对比模式的支持范围更窄：复杂内容可留在底稿中，不能任意跨侧复制；表格文字修改要求两侧表格结构一致。

## 使用前知道这些就够了

- 支持 `.docx`；旧版 `.doc` 请先用 Word 另存为 `.docx`。
- 章节合并/融合遇到修订、批注、脚注尾注、正文域、内容控件、嵌入对象及旧式 VML 图形，会提示先在副本中处理。
- 不自动润色、去重、清理引用或重编图表编号；正文中写死的章节编号也不会自动更新。
- 字体需要本机安装。浏览器预览是近似排版，导出后请在 Word 中核对分页、浮动图片和复杂版式。
- 最多 20 份文档，单份 25 MB，总压缩大小 100 MB、解压大小 250 MB、总段落数 10,000；每份来源最多 2,500 个正文块。
- 切换工作台会保留当前选择，刷新或关闭页面会清空。及时导出；JSON 记录用于审阅追踪，不能恢复项目。

## 样例与开发

[`examples/public`](examples/public) 提供三份从零制作的虚构文档，开箱即可体验。原始示例生成代码也包含在项目中，没有使用真实项目材料。

技术栈：**React + TypeScript + Vite**，使用 **JSZip** 处理 DOCX 包，使用 **diff** 比较文本，使用 **docx-preview** 在隔离的 iframe 内预览文档。

```bash
npm test                               # 自动化回归测试
npm run build                         # 类型检查与生产构建
npm run preview                       # 预览构建结果
node scripts/generate-examples.mjs     # 重新生成公开样例
node scripts/check-public-files.mjs    # 检查 Git 跟踪文件
```

核心代码路径：`chapterOutline.ts` 识别段落类型，`sections.ts` 构建可审阅的章节布局，`chapters.ts` 负责样式、编号、图片关系及最终文档组装。章节融合复用了原有导出引擎。

## 隐私与许可证

`tmp/`、个人 Word/PDF、生成结果、缓存和凭据默认不纳入 Git。公开 DOCX 仅放行三份明确列名的虚构样例；CI 会检查跟踪文件。请勿通过 `git add -f` 绕过这些规则，也不要在 Issue 中上传私人文档。
